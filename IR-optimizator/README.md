# IR-optimizator

Адаптация импульсных характеристик (IR) гитарных кабинетов под аппаратные загрузчики с ограничением на длину импульса — Pangaea CP-16M и подобные.

В подсистеме три утилиты:

- **`iroptimizator.py`** — подготовка IR: приведение к нужному формату с анализом исходника.
- **`irsummary.py`** — сводка по IR в PNG: АЧХ, форма импульса, спад энергии. Описана [в конце](#irsummarypy--сводка-по-ir-в-png).
- **`irblend.py`** — объединение двух IR: параллельно (бленд двух микрофонов или кабинетов, с выравниванием по времени и проверкой фазы) или последовательно (свёртка «усилитель → кабинет»). Описана [ниже](#irblendpy--объединение-двух-ir).

Скрипт `iroptimizator.py` приводит произвольный WAV-файл IR к заданному формату: моно, нужная частота дискретизации и битность, фиксированная длина в сэмплах, обрезка низа и верха фильтрами, плавное затухание в конце и нормализация пика.

## Возможности

- Ресемплинг 44.1 ↔ 48 кГц качественным полифазным фильтром (`scipy.signal.resample_poly`).
- Битность 16 или 24 бита (`PCM_16` / `PCM_24`); при 16 битах — TPDF-дизеринг и честное округление.
- Длина импульса на выбор: 512, 984, 1024 или 2048 сэмплов (произвольное значение — флагом `--len`).
- Доля энергии ниже HPF в отчёте и опциональный повторный HPF после обрезки (`--hpf-after`) — против низов, которые возвращает короткое окно.
- HPF 2-го порядка (12 дБ/окт) и LPF 4-го порядка (24 дБ/окт) с задаваемыми частотами среза; по умолчанию оба выключены, `0` отключает фильтр.
- Fade-out 2 мс (половина косинусного окна) в конце импульса — без щелчка на стыке.
- Отчёт по энергии: сколько процентов энергии импульса уложилось в выбранную длину и сколько снял fade-out.
- Нормализация на выбор: по пику до −1 dBFS (по умолчанию) или по громкости — K-взвешенной энергии IR, чтобы IR разного характера звучали одинаково громко.
- Итоговый файл всегда моно: стерео и дуал-моно сводятся усреднением каналов, с предупреждением о противофазе.
- Детект предзадержки: если в начале IR есть тишина, скрипт предупреждает и показывает, сколько сэмплов полезной части уцелеет после обрезки; `--trim` её удаляет.
- Исправление инвертированной полярности (`--fix-polarity`).
- Минимально-фазовое преобразование (`--minphase`, по умолчанию выключено) — с рекомендацией включить, если оно заметно поможет конкретному IR.
- Проверка исходника на брак (клиппинг, постоянное смещение, инвертированная полярность), оценка шумового пола и верности конвертации — насколько обработка изменила АЧХ.
- Спектральный анализ исходника: полезная полоса IR и обнаружение обрыва содержания (файл помечен 48 кГц, а ресемплирован вверх с меньшей).
- Пакетная обработка: несколько файлов за один запуск, по каждому — свой блок отчёта, в конце сводка с перечнем файлов, вызвавших предупреждения.

## Установка

```bash
cd IR-optimizator
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

## Запуск

Интерактивный режим — WAV передаётся аргументом, параметры запрашиваются по очереди, Enter принимает значение по умолчанию:

```bash
source venv/bin/activate
python iroptimizator.py "OH 412 DZL V30 JS.wav"
```

```
Частота дискретизации:
  1) 44.1 кГц
  2) 48 кГц  (по умолчанию)
Выбор [1-2, Enter = 2]:

Битность:
  1) 16 бит
  2) 24 бит  (по умолчанию)
Выбор [1-2, Enter = 2]:

Длина импульса:
  1) 512 сэмпл. (10.7 мс @ 48000 Гц)
  2) 984 сэмпл. (20.5 мс @ 48000 Гц)  (по умолчанию)
  3) 1024 сэмпл. (21.3 мс @ 48000 Гц)
  4) 2048 сэмпл. (42.7 мс @ 48000 Гц)
Выбор [1-4, Enter = 2]:

HPF, Гц [Enter = выкл.]:
LPF, Гц [Enter = выкл.]:

Нормализация:
  1) по пику (-1 dBFS)  (по умолчанию)
  2) по громкости (цель 8 dB, пик не выше -1 dBFS)
Выбор [1-2, Enter = 1]:
```

Неинтерактивный режим — любой параметр задаётся флагом, и соответствующий вопрос не задаётся:

```bash
# Полностью из командной строки
python iroptimizator.py *.wav -o out --sr 48 --bits 24 --len 984 --hpf 60 --lpf 8000

# Часть флагами, остальное спросит
python iroptimizator.py ir.wav --sr 44 --len 1024

# Без терминала (cron, пайплайн) — берутся значения по умолчанию
python iroptimizator.py ir.wav < /dev/null
```

## Вывод

Каждый файл получает свой блок: заголовок с именем и параметрами исходника, строки анализа, строка результата. При нескольких файлах блоки нумеруются и в конце печатается сводка.

```
[2/5] predelay_500.wav  (48000 Гц, 10100 сэмпл.)
  полоса до 10.2 кГц (порог -40 dB от пика спектра), признаков апсемплинга нет
  ВНИМАНИЕ — предзадержка 500 сэмпл. (10.42 мс, порог -60 dB от пика). Обрезка идёт
  от начала файла: полезной части останется 484 из 984 сэмпл.
  в 984 сэмпл. уложилось 98.75 % энергии импульса (fade-out снял ещё 0.47 %)
  ВНИМАНИЕ — за пределами окна осталось 1.25 % энергии, хвост импульса обрезан
  заметно. Стоит взять длину больше 984 сэмпл.
  → predelay_500_48k24b_984.wav: 48000 Гц, 984 сэмпл., 24 бит

...

Обработано файлов: 5, с предупреждениями 3: predelay_500.wav, upsampled_22to48.wav, silence.wav
```

Для одиночного файла номер `[i/N]` и сводка не выводятся. Каталог вывода печатается один раз в шапке, поэтому в строках результата стоят только имена файлов.

## Параметры

| Флаг | Значения | По умолчанию | Описание |
|---|---|---|---|
| `files` | пути к WAV | — | один или несколько исходных файлов (позиционный аргумент) |
| `-o`, `--outdir` | путь | `.` | каталог для результатов, создаётся при отсутствии |
| `--sr` | `44`, `48`, `44100`, `48000` | `48000` | целевая частота дискретизации |
| `--bits` | `16`, `24` | `24` | битность выходного файла |
| `--len` | целое > 0 | `984` | длина импульса в сэмплах (в меню — 512/984/1024/2048) |
| `--hpf` | Гц, `0` — выключить | выкл. | частота среза фильтра высоких частот |
| `--lpf` | Гц, `0` — выключить | выкл. | частота среза фильтра низких частот |
| `--hpf-after` | — | выкл. | повторить HPF после обрезки; срез −3 дБ смещается вверх в ~1.25 раза (см. [«HPF и короткое окно»](#hpf-и-короткое-окно)); только флагом, интерактивно не спрашивается; требует включённого HPF |
| `--minphase` | — | выкл. | заменить импульс минимально-фазовой версией с той же АЧХ (см. [«Минимальная фаза»](#минимальная-фаза)); суффикс `_minph` |
| `--fix-polarity` | — | выкл. | перевернуть импульс, если главный пик отрицательный |
| `--trim` | — | выкл. | удалить предзадержку — тишину до первого отсчёта выше −60 dB от пика |
| `--no-dither` | — | дизер вкл. | не применять TPDF-дизеринг при 16 битах (округление остаётся честным) |
| `--norm` | `peak`, `loudness` | `peak` | нормализация: по пику к −1 dBFS или по громкости (см. [«Нормализация по громкости»](#нормализация-по-громкости)) |
| `--loudness-target` | дБ | `8` | целевая громкость для `--norm loudness`; без `--norm` сама включает нормализацию по громкости, с `--norm peak` — ошибка |

HPF и LPF по умолчанию выключены: в 984 сэмплах HPF не даёт чистого среза — обрезка возвращает низы (подробно в разделе [«HPF и короткое окно»](#hpf-и-короткое-окно)), поэтому фильтры включаются только явно, флагом или ответом на вопрос. Прежние умолчания были HPF 60 Гц и LPF 8000 Гц.

Частоты среза проверяются на попадание в диапазон `0 < f < fs/2`: например, `--lpf 30000` при 44.1 кГц завершится ошибкой, а не падением `butter`.

## Имя выходного файла

К имени исходника добавляется суффикс с параметрами:

```
OH 412 DZL V30 JS.wav  →  OH 412 DZL V30 JS_48k24b_984.wav
```


Если у двух исходников из разных каталогов совпадают имена (`a/cab.wav` и `b/cab.wav`), результаты получили бы одно имя и второй затёр бы первый. Такой запуск останавливается с ошибкой до вопросов и до обработки, с перечнем конфликтующих файлов.
## Предзадержка

Обрезка до целевой длины идёт **от начала файла**, поэтому тишина в начале IR (предзадержка от расстояния до микрофона или от экспорта из DAW) съедает полезный хвост импульса. Скрипт её не удаляет и не сдвигает сигнал — только предупреждает:

```
ir.wav: ВНИМАНИЕ — предзадержка 500 сэмпл. (10.42 мс, порог -60 dB от пика).
Обрезка идёт от начала файла: полезной части останется 484 из 984 сэмпл.
```

Флаг `--trim` удаляет её: импульс начинается с первого отсчёта выше порога, и все 984 сэмпла уходят на сам импульс.

```
предзадержка 500 сэмпл. (10.42 мс) удалена — импульс начинается с первого отсчёта выше -60 dB от пика
```

Отсчёт на пороге лежит на −60 dB от пика, поэтому резать прямо по нему безопасно — скачок на такой громкости неслышен. Проверено: файл с 500 сэмплами тишины в начале после `--trim` даёт побитово тот же результат, что и файл без неё. Без флага предупреждение подсказывает `--trim`. Анализ шумового пола при удалённой предзадержке сравнивает хвост со сдвинутой точкой обрезки.

Предзадержкой считается число сэмплов до первого превышения порога `PREDELAY_THR_DB` = −60 dB относительно пика. Остаток пересчитывается в сэмплы целевой частоты, так что при 44.1 кГц те же 500 исходных сэмплов @48 кГц дадут другой остаток. Если предзадержки нет, сообщение не выводится.

Учти, что каузальные фильтры сами вносят групповую задержку (в основном LPF 4-го порядка) — пик сдвигается на несколько сэмплов. Это нормально для одиночного IR, но заметно при сложении обработанного импульса с сухим сигналом.

## Проверка исходника и верность конвертации

Перед обработкой исходник проверяется на брак, а после неё оценивается, насколько результат отличается от исходника.

**Клиппинг.** Ищутся плоские вершины: серии из `CLIP_RUN` = 3 и более отсчётов подряд на уровне пика канала. Это надёжнее, чем проверка на 0 dBFS: файл могли срезать при записи, а потом нормализовать ниже нуля, и тогда срезанные вершины стоят на любом уровне. Клиппинг — это искажение самого IR, обработка его не исправит, поэтому он выводится как предупреждение.

**Полярность.** Если главный пик отрицательный, это отмечается строкой без предупреждения. На звук одиночного IR это не влияет, но при смешивании с другим IR или прямым сигналом даст гашение. Флаг `--fix-polarity` переворачивает такой импульс; проверено, что перевёрнутый файл после исправления побитово совпадает с обработкой исходного. Знак проверяется по уже обработанному сигналу, а не по исходнику: при `--minphase` импульс строится только по АЧХ, и его знак от исходника не зависит.

**Шумовой пол.** Хвост считается шумом, если его уровень перестал падать: последние 10 % файла (но не меньше 10 мс, `NOISE_TAIL_MIN_MS`) не тише предыдущего такого же куска больше чем на `NOISE_PLATEAU_DB` = 3 dB. Тогда выводится уровень пола, момент, когда огибающая (скользящий RMS 5 мс) опускается до пола + 6 dB, и где относительно него приходится обрезка:

```
шумовой пол -95 dB, импульс уходит в шум на ~141 мс; обрезка на 20.5 мс (уровень -49 dB) раньше — хвост до ухода в шум теряется
```

Если уровень в конце файла ещё падает, пол считается не достигнутым и выводится уровень в конце и в точке обрезки. Хвост цифровой тишины (экспорт фиксированной длины, дополнение нулями) перед оценкой отрезается — уровень ниже `DIGITAL_SILENCE_DB` = −120 dB от пика считается тишиной, а в отчёт идёт отдельная строка «в конце файла 240 мс цифровой тишины — импульс заканчивается на 60 мс». Без этого нулевой хвост давал бессмысленное «пол не достигнут, в конце −600 dB». Минимальная длина кусков нужна потому, что на 2–3 мс затухающий хвост падает меньше чем на 3 dB и без неё ошибочно принимался бы за шум. Уровень в точке обрезки напрямую связан с полкой на низах (см. [«HPF и короткое окно»](#hpf-и-короткое-окно)): чем громче импульс там, где его режут, тем больше остаток.

**Постоянное смещение.** Если пол достигнут, проверяется среднее значение хвоста. Смещение выше `DC_WARN_DB` = −60 dB от пика, заметно превышающее случайное среднее шума (σ/√n), — признак смещения АЦП при записи; выводится предупреждение. В затухающем хвосте такая проверка бессмысленна: там ненулевое среднее — это сам сигнал.

**Верность конвертации.** АЧХ результата (сглаживание 1/3 октавы) сравнивается с эталоном — исходником, к которому применены те же фильтры, но на полной длине. Поэтому в отклонение попадает только то, что внесли обрезка, fade и повторный HPF, а не намеренное действие фильтров. Общий уровень выравнивается по медиане: нормализация пика меняет громкость, а не тембр.

```
отклонение АЧХ от исходника в 100 Гц–5.0 кГц: макс. 0.3 dB на 115 Гц, среднее 0.1 dB
```

Рабочая полоса — 100 Гц – 5 кГц, но нижний край поднимается до удвоенного разрешения окна (при 512 сэмплах — 188 Гц) и до 1.5 частоты HPF, а верхний опускается ниже LPF и полезной полосы. Ниже неё форму АЧХ задаёт уже сама обрезка, поэтому низы оцениваются отдельной строкой — см. ниже. Если отклонение больше `FIDELITY_WARN_DB` = 3 dB, выводится предупреждение: обычно это значит, что окно слишком короткое для этого IR. На кабинетных IR отклонение при 984 сэмплах — 0.1–0.4 dB, при 512 — до 0.7 dB, при 2048 — около нуля.

**Низы ниже рабочей полосы.** Отдельная строка показывает, что обрезка сделала с полосой от 40 Гц до нижнего края рабочей полосы (`LOW_BAND_LO_HZ`; при HPF — не ниже 1.5 его частоты):

```
низы 40–100 Гц (ниже рабочей полосы, ограничены длиной окна): подъём до +3.3 dB на 40 Гц, провал до -4.3 dB на 54 Гц
РЕКОМЕНДАЦИЯ — на низах окно 1024 сэмпл. заметно меняет тембр (до 4.3 dB); при 2048 сэмпл. — до 2.2 dB.
Если загрузчик принимает более длинные IR — возьмите длину больше.
```

Здесь два эффекта. **Подъём** — полка от незавершённого спада самого кабинета: динамик в корпусе — фильтр высоких частот, его спад во времени достигается медленным хвостом, который гасит низы начала импульса, и обрезка на 23 мс замораживает незавершённую компенсацию (тот же механизм, что у HPF, см. [«HPF и короткое окно»](#hpf-и-короткое-окно)). **Провал** — резонанс корпуса около 50–60 Гц: ему нужно время, чтобы прозвучать, и короткое окно его ослабляет. Это уже слышимый край диапазона — «удар» низа.

Показываются оба экстремума со знаком (меньше 0.5 dB не выводятся). Общий уровень выравнивается по рабочей полосе, а не по медиане самих низов — иначе равномерный провал всех низов «выровнялся» бы и пропал из оценки. Если отклонение больше `LOW_BAND_REC_DB` = 2 dB, появляется рекомендация с прогнозом для следующей длины из меню, посчитанным на том же эталоне; прогноз совпадает с реальным прогоном на этой длине. На тестовых кабинетах при 1024 сэмплах (44.1 кГц): `BD_DT_21GetDown` — до 1.3 dB, `BD_HV_3_AllYouNeed` — до 6.4 dB (полка), `BD_HV_4_FinalEncore` — до 4.3 dB (провал резонанса на 54 Гц); при 2048 — 0.6, 1.1 и 2.2 dB.

`--minphase` низам не помогает (уровни на 20 и 60 Гц не меняются — кабинеты и так почти минимально-фазовые), `--hpf-after` неприменим — низы здесь возвращает не фильтр, а сам кабинет. Полноценное решение — только длина.

## Сведение в моно

Выход всегда одноканальный — многоканальный вход усредняется до всей остальной обработки. Дуал-моно (идентичные каналы) сводится без потерь. О том, что произошло, сообщается в логе:

```
ir.wav: 2 канала сведены в моно (корреляция 1.00).
```

Два случая, когда усреднение портит результат, отмечаются отдельно:

```
ir.wav: ВНИМАНИЕ — каналы в противофазе (корреляция -1.00), при сведении в моно
они гасят друг друга: падение уровня полное. Проверьте полярность канала.

ir.wav: каналы слабо коррелированы (корреляция 0.17) — свод в моно даёт
гребёнчатую фильтрацию, уровень падает на 2.3 dB.
```

Первое — инвертированный по полярности канал: без предупреждения на выходе оказался бы файл с тишиной. Второе — два разнесённых микрофона: их сумма закономерно даёт гребёнку, это свойство самого свода, а не ошибка. Пороги — `ANTIPHASE_CORR` = −0.5 и `LOW_CORR` = 0.5 по минимальной попарной корреляции каналов.

## Спектральный анализ исходника

Перед обработкой каждый файл анализируется, и в лог выводится строка вида:

```
ir.wav: полезная полоса до 10.2 кГц (порог -40 dB от пика спектра), обрывов спектра нет
```

**Полезная полоса** — частота, выше которой в импульсе уже нет содержания (порог `BAND_THR_DB` = −40 dB от пика спектра). Подсказывает, куда осмысленно ставить LPF: если частота среза оказывается выше полосы, скрипт отдельно сообщает, что фильтр практически ничего не срезает.

**Обрыв содержания** определяется по провалу спектра над частотой Найквиста одного из стандартных значений — это след антиалиасного фильтра, оставшийся от ресемплинга вверх. Предупреждение выводится, только если обрыв ниже целевого Найквиста, то есть содержания действительно не хватает:

```
ir.wav: ВНИМАНИЕ — содержание обрывается на 11.0 кГц — ниже целевого Найквиста
24.0 кГц. Похоже, файл уже был ресемплирован вверх; ресемплинг до 48000 Гц
содержание не вернёт.
```

При понижении частоты (файл 96 кГц → цель 48 кГц) обрыв выше целевого Найквиста значения не имеет и предупреждения не вызывает — всё, что выше, срезается в любом случае. Сам факт обрыва при этом отмечается нейтральной строкой.

Два ограничения метода заложены в детект:

- **Край полосы записи не считается обрывом.** У любого АЦП антиалиасный фильтр стоит чуть ниже Найквиста, поэтому честная запись на 96 кГц обрывается около 45 кГц просто по устройству тракта. Кандидаты выше `EDGE_OF_BAND` = 0.85 от Найквиста файла пропускаются, иначе каждый файл 96 кГц объявлялся бы апсемплированным с 88.2 кГц.
- **Отсутствие обрыва не доказывает, что файл нативный.** У гитарного IR содержание кончается на 10–19 кГц, поэтому полосы по обе стороны от 22.05 кГц одинаково пусты, и 44.1 кГц от 48 кГц для такого материала неотличимы в принципе. Детект надёжно ловит только заметный обрыв — с 22.05 кГц и ниже.

Точность определения частоты обрыва — в пределах соседнего кандидата, поэтому при сравнении с целевым Найквистом берётся запас `CUTOFF_MARGIN` = 0.9: файл 48 → 96 кГц, возвращаемый на 48 кГц, предупреждения не вызывает, хотя обрыв у него определяется как 22.1 кГц вместо 24.

Оба измерения не зависят от предзадержки: для детекта обрыва сигнал выравнивается по началу импульса, и файл со сдвигом даёт те же цифры, что и без него.

## Сколько импульса уложилось в окно

После обрезки выводится доля энергии, оставшаяся в окне, — отсчитывается от энергии отфильтрованного импульса на его полной длине:

```
ir.wav: в 984 сэмпл. уложилось 99.62 % энергии импульса (fade-out снял ещё 0.02 %)
```

Если в окно попало меньше `ENERGY_WARN_PCT` = 99 %, добавляется предупреждение с советом взять длину больше. Для кабинетного IR цифры выглядят примерно так (48 кГц, LPF 8 кГц):

| Длина | Энергии в окне | Снял fade-out |
|---|---|---|
| 512 | 99.05 % | 0.48 % |
| 984 | 99.62 % | 0.02 % |
| 1024 | 99.65 % | 0.03 % |
| 2048 | 99.88 % | 0.00 % |

Файл без сигнала отмечается отдельной строкой вместо «уложилось 0 %».

### Корректность fade-out

Окно `0.5·(1 + cos(t))`, `t` от 0 до π, применяется к последним `FADE_MS` = 2 мс **до** нормализации, поэтому нормализация учитывает его влияние на пик. Свойства проверены: окно монотонно убывает, начинается ровно с 1.0 (на входе в спад разрыва нет), кончается ровно нулём, производная на обоих стыках нулевая — стык гладкий по первой производной.

Без fade-out на срезе остался бы разрыв уровнем −37 dB от пика при длине 512 и −56 dB при 2048 — это слышимый щелчок, ради него fade и нужен. Плата за него видна в таблице выше: на коротком окне он снимает полпроцента энергии, на длинном — сотые доли.

## HPF и короткое окно

HPF работает на полной длине IR, до обрезки, — и там честно давит низы: при срезе 80 Гц уровень 20 Гц уходит примерно на −58 dB. Но обрезка до 984 сэмплов (20.5 мс) возвращает часть низов обратно, и на графике АЧХ ниже ~40 Гц появляется полка около −30 dB. Период волны 30 Гц — 33 мс, длиннее всего импульса, а разрешение окна по частоте около 49 Гц: такой короткий импульс физически не может нести форму АЧХ ниже этого предела. Отрезанный медленный хвост фильтра оставляет постоянную составляющую (до обрезки −67 dB от максимума спектра, после — −30 dB).

Чтобы это было видно в цифрах, отчёт показывает долю энергии готового импульса ниже частоты HPF:

```
энергия ниже HPF 80 Гц: 0.27 %
```

Места эти низы не занимают: число сэмплов фиксировано, низкие частоты не вытесняют средние, а лишь накладываются медленной волной на всё окно. Проверено на оптимальной задаче «минимум энергии ниже среза при сохранении всего, что выше»: если верх не трогать, убрать удаётся 0.01 процентного пункта. Остаток ниже среза не отделим от полезного содержания — это его растекание из-за конечного окна.

Флаг `--hpf-after` повторяет HPF после обрезки и снова давит вернувшиеся низы:

```
энергия ниже HPF 80 Гц: 0.27 % → 0.10 % (повторный HPF после обрезки;
фактический срез −3 дБ смещается с 80 до ~100 Гц)
```

**Цена — смещение среза.** Два прохода HPF 2-го порядка дают на заданной частоте уже −6 дБ, и точка −3 дБ уезжает вверх ровно в 1.2465 раза: 80 Гц → ~100 Гц, 100 → ~125, 120 → ~150. Это свойство самих фильтров Баттерворта (`hpf_after_corner()` считает его из порядка фильтра), поэтому фактический срез печатается и в строке параметров, и в отчёте. На графике `irsummary` это видно по полосе −3 дБ в таблице метрик и по более позднему подъёму кривой.

| Срез, длина 984 | Фактический срез | Энергия ниже среза | 20 Гц без / с флагом |
|---|---|---|---|
| 60 Гц | ~75 Гц | ×0.89 — почти без выигрыша | −29.9 / −26.8 dB |
| 80 Гц | ~100 Гц | ×0.37 | −28.5 / −39.8 dB |
| 100 Гц | ~125 Гц | ×0.37 | −30.4 / −38.5 dB |
| 120 Гц | ~150 Гц | ×0.36 | −32.7 / −47.1 dB |

**Убрать полку и сохранить срез одновременно в 984 сэмплах нельзя.** Проверено: если поставить оба прохода на 80 / 1.2465 = 64.2 Гц (`--hpf 64 --hpf-after`), суммарные −3 дБ возвращаются на 80 Гц, но выигрыш почти пропадает — 20 Гц снова около −28.5 dB, энергия ниже 80 Гц 0.22 % вместо 0.10 %. Второй проход на 64 Гц слишком близок к пределу разрешения окна (~49 Гц), и обрезка возвращает низы обратно. Выбор получается такой: либо срез на месте и полка около −30 dB, либо полка убрана и срез на ~25 % выше.

Когда срез близок к пределу разрешения окна (`частота / длина`, при 984 сэмплах около 49 Гц), флаг почти не помогает, а на самых низких частотах становится даже громче: звон фильтра длиннее окна, и обрезка возвращает низы обратно. Если энергия ниже среза падает меньше чем на 30 % (`HPF_AFTER_MIN_GAIN` = 0.7), скрипт предупреждает, что флаг здесь лучше не использовать. На длинном окне тот же срез 60 Гц снова работает: при 2048 сэмплах 0.03 % → 0.01 %.

**Почему обработанный файл на самых низах бывает громче исходника.** При сравнении в `irsummary` исходник без HPF на 20 Гц оказывается ниже результата с HPF (−35.7 против −28.5 dB). По отдельности обе операции ведут себя нормально: HPF на полной длине опускает 20 Гц до −57.8 dB, обрезка без HPF оставляет те же −35.7 dB. Парадокс даёт только их сочетание. HPF не стирает низы мгновенно: он превращает их в медленное колебание около частоты среза, которое гасится за десятки миллисекунд. Накопленная сумма отсчётов отфильтрованного импульса раскачивается (−1.73 на 2 мс, +0.27 на 5 мс, −0.70 на 12 мс) и сходится к нулю только к ~40 мс. К 20.5 мс колебание не завершено — сумма стоит на +0.43 против +0.24 у исходника без фильтра, — и обрезка замораживает этот недокомпенсированный остаток как постоянную составляющую. Поэтому на 2048 сэмплах (43 мс) полка уходит на −56 dB, а `--hpf-after` гасит уже замороженный остаток внутри окна. Нормировка графика тут ни при чём: максимумы кривых стоят в одном месте.

Флаг требует включённого HPF. Раз HPF по умолчанию выключен, `--hpf-after` без `--hpf` в неинтерактивном запуске завершается ошибкой «`--hpf-after` требует частоту HPF», а `--hpf 0 --hpf-after` — ошибкой «требует включённого HPF»; код выхода 1. В интерактивном режиме вопрос про HPF при этом становится обязательным: ни Enter, ни 0 не принимаются. Раньше флаг в такой ситуации тихо игнорировался с кодом 0, и скрипт, ждущий файлы `_hpfpost`, получал обычные.

Файл с повторным HPF получает суффикс `_hpfpost` (`ir_48k24b_984_hpfpost.wav`), чтобы не затирать обычный. HPF 4-го порядка вместо повторного прохода — не замена: его звон ещё длиннее, и после обрезки на 20 Гц выходит хуже (−23 dB против −30).

## Нормализация по громкости

При нормализации по пику все IR приводятся к −1 dBFS, но громкость на выходе свёртки определяет не пик, а энергия IR. У кабинетов с близким микрофоном энергия сосредоточена в первой миллисекунде, и пиковая нормализация почти совпадает с нормализацией по громкости: на пяти тестовых кабинетах разброс громкости всего 0.8 dB. Но IR с энергией, размазанной во времени (далёкий микрофон, комната), при той же пиковой нормализации оказывается громче — синтетический «комнатный» импульс на 13.7 dB. При переключении пресетов такие IR «прыгают» по уровню.

`--norm loudness` (или пункт 2 в интерактивном вопросе) приводит к одинаковой громкости. Мера — энергия IR после K-фильтра ITU-R BS.1770, основы LUFS: для широкополосного сигнала на входе уровень на выходе свёртки пропорционален энергии IR, а K-фильтр (полка +4 дБ выше ~1.7 кГц и HPF ~38 Гц) учитывает чувствительность слуха. Коэффициенты фильтра пересчитываются для частоты дискретизации и на 48 кГц совпадают с таблицей стандарта до машинной точности.

```
громкость 8.0 dB (K-взвеш. энергия), пик -2.1 dBFS — нормализовано по громкости, цель 8 dB
```

**Цель абсолютная**, а не «по самому тихому в пачке»: IR, сконвертированные в разные дни, совпадают по громкости между собой. По умолчанию 8 dB — чуть ниже, чем у кабинетов с близким микрофоном при пике −1 dBFS (8.3–9.1 dB), так что такие кабинеты почти не меняются (тише на 0.3–1.1 dB), а громкие IR убавляются до их уровня. Сдвинуть цель — `--loudness-target`. Цель привязана к частоте дискретизации: у одного и того же импульса на 48 кГц отсчётов больше, чем на 44.1 кГц, и энергия выше на 0.4 dB, поэтому сравнивать громкость имеет смысл между файлами одной частоты — как они и звучат в одном устройстве.

**Пик не выше −1 dBFS.** Если IR с острым пиком и малой энергией при целевой громкости ушёл бы в клиппинг, пик ограничивается, а в отчёте появляется предупреждение «до целевой громкости не хватает X dB» — такой файл будет тише остальных, и это видно сразу. Помогает понизить цель.

Громкость печатается и при нормализации по пику — так видно, насколько кабинеты различаются. Файлы, нормализованные по громкости, получают суффикс `_loud`, чтобы не затирать версии «по пику». Режим «по пику» остался побитово прежним.

## Минимальная фаза

`--minphase` заменяет импульс минимально-фазовой версией с той же АЧХ. Из всех сигналов с данной АЧХ у минимально-фазового энергия максимально сдвинута к началу, поэтому при любой длине обрезки он сохраняет больше энергии. Строится гомоморфным методом через кепстр; АЧХ результата на полной длине совпадает с исходником (проверено на всех тестовых файлах: расхождение 0.000 dB). Цена — меняется фаза, то есть временной характер импульса, и на слух он может звучать иначе. Поэтому опция по умолчанию выключена.

**Рекомендация включить её появляется сама**, если она заметно поможет. Для каждого файла скрипт считает минимально-фазовую версию и сравнивает с исходной обрезкой напрямую: рекомендация выводится, если энергия в окне растёт хотя бы на 1 процентный пункт (`MINPHASE_GAIN_PP`) или отклонение АЧХ уменьшается хотя бы на 1 dB (`MINPHASE_GAIN_DB`):

```
РЕКОМЕНДАЦИЯ — включите --minphase: минимально-фазовая версия уложит в окно больше импульса —
энергия в окне 64.6 → 67.4 %, отклонение АЧХ 5.1 → 4.1 dB. Фаза при этом меняется, временной
характер импульса может звучать иначе.
```

В пакетной сводке файлы с рекомендациями перечисляются отдельной строкой. С включённой опцией отчёт показывает, что она дала, и честно сообщает, если почти ничего:

```
минимально-фазовое преобразование: энергия в окне 99.9 → 99.9 %, отклонение АЧХ 0.1 → 0.1 dB —
на этом IR почти ничего не даёт, импульс и так близок к минимально-фазовому
```

Кабинеты с близким микрофоном почти минимально-фазовые: динамик сам по себе близок к минимально-фазовой системе, а большой задержки и отражений в таком IR нет. На трёх тестовых кабинетах выигрыш около 0.01 п.п., рекомендация не появляется. Помогает она IR с далёким микрофоном, комнатным звуком и отражениями: на синтетическом «комнатном» импульсе при 1024 сэмплах энергия в окне 64.6 → 67.4 %, отклонение АЧХ 5.1 → 4.1 dB; при 512 — 35.8 → 42.0 % и 9.9 → 7.2 dB.

Минимально-фазовая версия начинается сразу, без задержки, поэтому предзадержка при `--minphase` уходит сама, и `--trim` вместе с ним не нужен. Файл получает суффикс `_minph`.

## 16 бит: дизеринг и округление

При 16 битах квантование делается в самом скрипте, а не в libsndfile. Измерено, что libsndfile при записи float в int16 отбрасывает дробную часть, а не округляет: средняя ошибка −0.5 младшего разряда, RMS 0.58 LSB вместо 0.29 — постоянное смещение на полразряда и шум на 6 dB выше необходимого.

По умолчанию добавляется **TPDF-дизер** — шум с треугольным распределением ±1 LSB до округления. Без него ошибка квантования тихого сигнала коррелирована с ним и даёт дискретные искажения: на синусе в несколько LSB выбросы в спектре ошибки на 46–72 dB над уровнем шума. С дизером ошибка — ровный шум около −96 dBFS (RMS 0.5 LSB), не зависящий от сигнала. Генератор шума с фиксированным зерном, поэтому повторный запуск даёт тот же файл. `--no-dither` отключает дизер, округление при этом остаётся честным (RMS 0.29 LSB, без смещения).

Честная оговорка: для кабинетных IR длиной 984–1024 сэмпла эффект на слух ничтожен. Их хвост в окне звучит около −49 dBFS, почти на 50 dB выше младшего разряда 16 бит, а абсолютный уровень устраняемых искажений — около −100 dBFS. Дизер здесь — правильная гигиена, заметной станет разница у IR с тихими хвостами и на участке fade-out.

При 24 битах дизер не нужен (шум квантования около −144 dBFS), и запись остаётся за libsndfile — её отбрасывание дроби там равно −144 dBFS, а 24-битные файлы побитово совпадают с прежними.

## Порядок обработки

1. Стерео → моно (усреднение каналов).
2. `--trim`: срез предзадержки в отсчётах исходника.
3. Ресемплинг до целевой частоты, если она отличается от исходной.
4. HPF, затем LPF — каузально (`sosfilt`), на **полной** длине IR: хвосты самих фильтров не обрезаются раньше времени и нет пре-ринга. Результат сохраняется как эталон для оценок верности конвертации и выигрыша от `--minphase`.
5. `--minphase`: замена импульса минимально-фазовой версией.
6. Проверка знака главного пика уже обработанного сигнала; с `--fix-polarity` импульс переворачивается.
7. Обрезка или дополнение нулями до заданной длины.
8. Fade-out 2 мс (96 сэмплов @ 48 кГц, 88 @ 44.1 кГц) половиной косинусного окна; если импульс короче fade — окно укорачивается до его длины.
9. `--hpf-after`: повторный HPF и повторный fade-out — хвост второго фильтра за окном отрезается, и без повторного fade на конце снова был бы обрыв.
10. Нормализация: по пику до −1 dBFS или по громкости с ограничением пика −1 dBFS (файл из одной тишины не вызывает деления на ноль).
11. Запись: 16 бит квантуются в скрипте с округлением и по умолчанию с TPDF-дизером, 24 бита пишет libsndfile.

Порядки фильтров фиксированы в константах `HPF_ORDER = 2` и `LPF_ORDER = 4`, длительность fade — в `FADE_MS`, целевой пик — в `PEAK_DBFS`, пороги анализа — в `PREDELAY_THR_DB`, `BAND_THR_DB`, `NATIVE_GAP_DB`, `ANTIPHASE_CORR`, `LOW_CORR`, `ENERGY_WARN_PCT`, `HPF_AFTER_MIN_GAIN`, `MINPHASE_GAIN_PP`, `MINPHASE_GAIN_DB`, `CLIP_RUN`, `DC_WARN_DB`, `NOISE_PLATEAU_DB`, `NOISE_MARGIN_DB`, `FIDELITY_WARN_DB` и `LOW_BAND_REC_DB`.

## Ресемплинг и нормализация

Ресемплинг выполняет **soxr** (SoX Resampler) с качеством `VHQ`. Если модуль не установлен, используется запасной путь — `scipy.signal.resample_poly`, и скрипт предупреждает об этом в выводе. Каким ресемплером считали, видно в отчёте:

```
ресемплинг 48000 → 44100 Гц (soxr VHQ)
```

Разница не косметическая. Измерено на чистых синусах при 48 → 44.1 кГц:

| Частота входа | `resample_poly` | `soxr` VHQ |
|---|---|---|
| 21.0 кГц (проходная полоса) | −2.6 dB | −4.1 dB |
| 22.0 кГц | −5.8 dB | **−137 dB** |
| 22.5 кГц (алиас) | −8.2 dB | **−194 dB** |
| 23.9 кГц (алиас) | −16.5 dB | **−190 dB** |

У `resample_poly` длина FIR фиксирована (≈10·max(up, down) отсчётов), поэтому переходная полоса размазана на 20–24 кГц вместо обрыва на 22.05: алиасы подавляются всего на 8–16 дБ. У `soxr` обрыв честный, и работает он при этом быстрее (0.23 против 0.36 мс на прогон).

Для кабинетных IR с последующим LPF 8 кГц разница на выходе невелика — результаты двух ресемплеров расходятся на −64 дБ от уровня сигнала. Она становится значимой при `--lpf 0` и материале с содержанием у самой частоты Найквиста.

ffmpeg для этого не нужен: `soundfile` (libsndfile 1.2.2) читает WAV, AIFF, FLAC, OGG, CAF, W64, RF64 и MP3, а `soxr` — та же библиотека ресемплинга, что внутри ffmpeg, но подключается импортом, без внешнего процесса и разбора его вывода.

Нормализация стоит последним шагом намеренно. Ресемплинг поднимает пик, восстанавливая интерсэмпл-пики, которых не было в исходной сетке отсчётов: на тестовом IR 48 → 44.1 кГц пик вырос с 0.9886 до 0.9990 (+0.09 dB), а фильтры затем сдвинули его на −0.39 dB. Нормализованный до 0 dBFS *до* ресемплинга файл после него клиппировал бы при записи в целочисленный PCM; запас −1 dBFS дополнительно покрывает интерсэмпл-пики при воспроизведении.

- `numpy`, `scipy`, `soundfile`, `soxr`, `matplotlib` (см. `requirements.txt`)
- `soxr` формально необязателен — без него ресемплинг идёт через `resample_poly` с предупреждением

## `irsummary.py` — сводка по IR в PNG

Рисует в один PNG:

1. **АЧХ** — логарифмическая ось 20 Гц – 20 кГц, сглаживание 1/3 октавы; кривые выровнены по среднему уровню в полосе 200 Гц – 2 кГц (`--align peak` — по максимуму). Серая зона — где форму АЧХ задаёт уже длина окна, а не кабинет.
2. **Спектральный распад (CSD)** — для одного файла: тепловая карта «частота × время», видно резонансы, которые звенят дольше остального. При сравнении нескольких файлов эту панель занимает **разница АЧХ**: для пар «исходник → результат» — каждого результата относительно его исходника, иначе — относительно первого файла.
3. **Форма импульса** — амплитуда по времени; видно атаку и предзадержку. Пунктир цвета кривой — конец файла, если он попадает в окно панели.
4. **Спад энергии** — огибающая в дБ; видно длину хвоста.
5. **Энергия по полуоктавным полосам** — 18 столбиков 31 Гц – 11 кГц (центры 1000·2^(n/2), полоса ±¼ октавы), тембральный баланс одним взглядом. Полуоктавы вдвое подробнее октав. Снизу — с 31 Гц, чтобы видеть основной тон нижней струны восьмиструнки (F#1 ≈ 46 Гц, Drop E ≈ 41 Гц — полоса «44»); сверху — до 11 кГц, где виден спад динамика. Полосы ниже 2·частота/длина самого короткого файла закрашены серым, как на АЧХ: у IR на 984 сэмпла (ниже ~98 Гц) их уровень задаёт длина окна, а не кабинет.
6. **Таблица метрик** — по строке на файл.

Метрики в таблице: длина (сэмплы / мс), частота дискретизации, пик в dBFS, предзадержка, полоса по уровням −3 и −10 дБ, частота пика АЧХ, спектральный центроид («яркость»), время спада на 20 дБ от пика, громкость (K-взвешенная энергия, та же мера, что у `iroptimizator.py --norm loudness`). Длинные имена в таблице сокращаются с середины, чтобы отличающийся конец (`…_984`, `…_984_prev`) оставался виден.

```bash
source venv/bin/activate

# Все *.wav в текущей папке — без аргументов
python irsummary.py

# Сводка по одному файлу — с картой спектрального распада
python irsummary.py "OH 412 DZL V30 JS.wav" -o summary.png

# Сравнение исходника с результатом обработки — с разницей АЧХ
python irsummary.py original.wav original_48k24b_984.wav -o compare.png

# Пакет: отдельный PNG на каждый файл
python irsummary.py cabs/*.wav --separate -o png/
```

| Флаг | Значения | По умолчанию | Описание |
|---|---|---|---|
| `files` | пути к WAV | все `*.wav` в текущей папке | один или несколько файлов; без аргументов берутся все `*.wav` текущей папки в алфавитном порядке |
| `-o`, `--out` | путь | `irsummary.png` / `.` | PNG при наложении, каталог при `--separate` |
| `--separate` | — | выкл. | отдельный PNG на файл вместо наложения |
| `--smooth` | целое ≥ 0 | `3` | сглаживание 1/N октавы, `0` — без сглаживания |
| `--tmax` | мс | авто | окно панелей времени; по умолчанию подбирается по спаду энергии |
| `--dpi` | целое | `150` | разрешение PNG |
| `--align` | `band`, `peak` | `band` | выравнивание кривых АЧХ: средний уровень 200 Гц – 2 кГц к 0 дБ или максимум к 0 дБ |

Ширина картинки — 18 дюймов (2700 px при `--dpi 150` до обрезки полей): 16 полос на восемь файлов — это 128 столбиков, им нужно место.

Без аргументов берутся все `*.wav` текущей папки — удобно в каталоге с исходниками и результатами конвертации: пары «исходник → результат» найдутся сами. Если `*.wav` нет, выводится ошибка. Без `--separate` все файлы накладываются на одни оси с легендой — основной сценарий сравнения. Больше восьми кривых на одном графике не различить, поэтому такой запуск отклоняется с советом взять `--separate` или указать файлы явно — в том числе когда файлы взяты из папки автоматически: молча переключаться на отдельные картинки скрипт не будет, это другой результат. С `--separate` совпадающие имена файлов из разных каталогов останавливают запуск до отрисовки — иначе картинки затёрли бы друг друга.

**Пары «исходник → результат».** Если в пачке есть и исходник, и результат `iroptimizator.py` (`X.wav` и `X_48k24b_984….wav`, в том числе переименованный вроде `X_48k24b_984_prev.wav`), разница АЧХ строится для каждого результата относительно его исходника, а не всех относительно первого файла. Найденные пары печатаются в терминале. Удобно запускать прямо `irsummary.py *.wav` в каталоге с исходниками и результатами: панель разницы сразу показывает, что изменила конвертация. При нескольких кандидатах в исходники берётся самый длинный (`cab_2`, а не `cab`).

**Выравнивание кривых.** По умолчанию каждая АЧХ сдвигается так, чтобы её средний уровень в полосе 200 Гц – 2 кГц был 0 дБ. При выравнивании по максимуму (`--align peak`, как было раньше) один резонанс сдвигал всю кривую, и разница тембра маскировалась разницей пиков. Разница АЧХ считается по выровненным кривым.

**Граница окна.** На АЧХ и разнице АЧХ серым закрашена полоса ниже удвоенного разрешения окна самого короткого файла (`2 · частота / длина`, при 984 сэмплах на 48 кГц — 98 Гц): там форму АЧХ задаёт уже длина окна — полка от незавершённого спада кабинета и недозвучавший резонанс корпуса, — а не сам кабинет. Это та же зона, которую `iroptimizator.py` оценивает строкой «низы».

Окно панелей времени по умолчанию подбирается само: панель импульса и карта распада показывают участок, пока спад энергии держится выше −30 дБ, панель спада — выше −40 дБ (но не больше 50 мс). Поэтому 200-миллисекундный IR не выглядит импульсом, сплющенным в левый край.

Оформление — светлая тема и категориальная палитра из восьми цветов, различимых и при нарушениях цветового зрения; цвета закреплены за позицией файла в фиксированном порядке, для карты распада — последовательная шкала одного тона. Легенда появляется при двух и более кривых, для единственной её заменяет заголовок с именем файла и параметрами. Имя файла в таблице метрик обведено цветом своей серии, так что идентичность не держится на одном лишь цвете кривой.

Детали реализации, без которых график врёт или разъезжается:

- **Длина преобразования** — не меньше 2¹⁷ отсчётов. Полоса 1/3 октавы на 30 Гц шириной всего 7 Гц, и при коротком FFT в неё попадает меньше одного бина — кривая идёт ступеньками.
- **Огибающая спада считается скользящим RMS**, а не преобразованием Гильберта: оно нелокально и на резком конце файла рисует несуществующий всплеск энергии в последних миллисекундах.
- **Имя файла — первая колонка таблицы, а не подпись строки**: подписи строк matplotlib рисует вне осей, и они уезжают за край картинки.
- **`tight_layout` не применяется** — он несовместим с таблицей и цветовой шкалой (выдаёт предупреждение и портит раскладку). Поля заданы явно, лишние края снимает `bbox_inches='tight'`.

- **Время спада −20 дБ считается от пика огибающей**, а не от начала файла: в тихой предзадержке огибающая около −600 дБ, и поиск с нуля сразу находил «спад» (0.5 мс вместо 3.4 при 200 сэмплах тишины).
- **Прямые подписи кривых ставятся внутри оси**, немного левее правого края, и раздвигаются по вертикали. Раньше подпись стояла ровно на правой границе с выравниванием влево и обрезкой по оси — целиком за краем, и её не было видно никогда.
- **Разница АЧХ при разной частоте дискретизации** рисуется только там, где у файла есть данные: выше Найквиста файла с меньшей частотой `np.interp` подставлял бы его последнее значение — выдуманную плоскую «разницу».

Метрики в терминале (полоса, предзадержка) берутся из `iroptimizator.py` импортом — чтобы цифры в двух утилитах совпадали.

## `irblend.py` — объединение двух IR

Объединяет два IR в один одним из двух способов — они принципиально разные, поэтому режим спрашивается первым вопросом (или задаётся `--mode`):

- **Параллельно** (`parallel`, по умолчанию) — бленд двух микрофонов или кабинетов: звук идёт двумя путями одновременно, и пути суммируются, y = a·A + b·B. Здесь нужны выравнивание по времени и проверка фазы — при сложении расхождение фаз даёт гребёнку.
- **Последовательно** (`serial`) — цепочка «усилитель → кабинет»: сигнал проходит через оба узла по очереди, и общий IR — это свёртка A ∗ B. Её АЧХ — произведение АЧХ (в дБ — сумма), длина — сумма длин минус один, порядок значения не имеет. Выравнивание и баланс не нужны: суммирования нет, гребёнке неоткуда взяться.

Параллельный режим: Строится на тех же функциях, что `iroptimizator.py`: чтение и свод каналов, ресемплинг soxr, детект предзадержки, K-взвешенная громкость, обрезка с fade, нормализация, 16-битный дизер.

```bash
source venv/bin/activate

# Интерактивно: спросит режим, частоту, битность, длину, баланс (для параллельного), нормализацию
python irblend.py BD_DT_21GetDown.wav OH_412_DZL_V30.wav

# Последовательно: IR оконечника свёртывается с IR кабинета
python irblend.py PWRAMPIR_6L6_D50_P70.wav BD_DT_20HellHola.wav --mode serial

# Полностью из командной строки
python irblend.py A.wav B.wav -o out --sr 44 --bits 24 --len 1024 --mix 70/30 --norm peak
```

Файлов — ровно два, A и B; иначе ошибка.

| Флаг | Значения | По умолчанию | Описание |
|---|---|---|---|
| `-o`, `--outdir` | путь | `.` | каталог вывода |
| `--mode` | `parallel`, `serial` | `parallel` | сложение (бленд) или свёртка (усилитель → кабинет) |
| `--sr` | `44`, `48` | `48` | частота результата; оба входа приводятся к ней |
| `--bits` | `16`, `24` | `24` | битность результата |
| `--len` | целое > 0 | `984` | длина результата (в меню — 512/984/1024/2048) |
| `--mix` | `40/60`, `40:60` или `40` | `50/50` | баланс: пропорция A/B или доля A в процентах; сумма не обязана быть 100 — `2/1` это 66.7/33.3. Только для параллельного режима: с `--mode serial` — ошибка; без `--mode` сам выбирает параллельный |
| `--norm` | `peak`, `loudness` | `peak` | нормализация результата |
| `--loudness-target` | дБ | `8` | цель для `--norm loudness`; без `--norm` включает её сама |
| `--fix-polarity` | — | выкл. | перевернуть результат, если главный пик отрицательный |
| `--no-dither` | — | дизер вкл. | не применять TPDF-дизеринг при 16 битах |

Порядок работы:

1. **Входы.** Каждый сводится в моно (с проверкой противофазы каналов) и ресемплируется к целевой частоте.
2. **Выравнивание по времени**, в два шага. Сначала у обоих срезается предзадержка по порогу −60 dB от пика — начала совпадают. Затем сдвиг B подстраивается по взаимной корреляции первых 5 мс в пределах ±2 мс: порог может сработать на тихом предвестнике, а слышно совпадение основной энергии. Проверено: при предвестнике за 10 сэмплов до начала подстройка возвращает ровно +10.
3. **Фаза.** Если корреляция в найденной точке отрицательная, B в противофазе с A — он переворачивается, иначе импульсы гасили бы друг друга. Проверено: A плюс тот же A, задержанный на 37 сэмплов, перевёрнутый и на 6 dB тише, после выравнивания и переворота даёт результат, совпадающий с обработкой одного A до младшего разряда 24 бит.
4. **Громкость** обоих выравнивается по K-взвешенной энергии (та же мера, что у `--norm loudness`), и баланс задаётся уже поверх: 50/50 — это поровну на слух, а не поровну по пику. Баланс — доли амплитуды: 70/30 — это A громче B на 7.4 dB. Вводится пропорцией A/B («40/60», «40:60») или долей A в процентах («40»); пропорция с суммой не 100 тоже годится («2/1» → 66.7/33.3), результат округляется до десятой — он же идёт в имя файла.
5. **Проверка на гребёнку.** Мощность смеси сравнивается с суммой мощностей слагаемых (1/6 октавы, 100 Гц – 10 кГц): где фазы A и B расходятся, смесь тише суммы. Провал глубже −6 dB — предупреждение с частотой и глубиной. Это не обязательно ошибка — у бленда разных микрофонов провалы бывают частью задуманного звука, — но такое стоит прослушать.
6. **Результат** — обрезка до длины, fade-out и нормализация через ту же `process()`, что в `iroptimizator.py`.

```
Выравнивание и фаза
  предзадержка срезана: A 0 сэмпл., B 0 сэмпл.
  подстройка по корреляции первых 5 мс: сдвиг не нужен, корреляция +0.88
  громкости выровнены: B +0.3 dB относительно A до выравнивания
  корреляция A и B в окне 1024 сэмпл.: +0.87; заметных провалов от сложения нет
```

Подстройка по корреляции убирает всё, что устраняется одним сдвигом: чистую задержку и даже частичные фазовые расхождения — сдвиг выбирается так, чтобы основная энергия сложилась синфазно, а гребёнка ушла за пределы рабочей полосы. Предупреждение остаётся для того, что сдвигом не лечится: фазового расхождения, зависящего от частоты. Проверено фазовращателем (all-pass) на 1 кГц: АЧХ та же, но около 1 кГц фаза повёрнута на 180° — провал −14.4 dB на 992 Гц и предупреждение.

**Последовательный режим.** Предзадержки при свёртке складываются, поэтому у обоих входов они срезаются. Затем свёртка и та же обрезка, fade и нормализация. Отчёт показывает окраску АЧХ каждого входа и итоговую — самый большой подъём и спад относительно среднего уровня 200 Гц – 2 кГц:

```
A: PWRAMPIR_6L6_D50_P70.wav  (48000 Гц, 2409 сэмпл.)
  окраска АЧХ (0 dB = средний уровень 200 Гц–2 кГц): подъём до +4.0 dB на 12000 Гц, спад до -0.4 dB на 701 Гц
B: BD_DT_20HellHola.wav  (48000 Гц, 10000 сэмпл.)
  окраска АЧХ (0 dB = средний уровень 200 Гц–2 кГц): подъём до +5.2 dB на 160 Гц, спад до -28.4 dB на 12000 Гц
Свёртка
  свёртка A ∗ B: 2409 + 10000 − 1 = 12408 сэмпл. (258.5 мс)
  итоговая окраска АЧХ (0 dB = средний уровень 200 Гц–2 кГц): подъём до +6.3 dB на 149 Гц, спад до -24.4 dB на 12000 Гц
Результат
  в 984 сэмпл. уложилось 99.89 % энергии свёртки (fade-out снял ещё 0.02 %)
```

Проверено: АЧХ свёртки совпадает с суммой АЧХ усилителя и кабинета в дБ с точностью до 0.2 dB (остаток — от сглаживания 1/3 октавы). IR оконечника короткий (спад на −40 dB за ~10 мс), поэтому длинная свёртка почти целиком укладывается в окно.

Оговорка по смыслу: IR снимает только линейную часть — АЧХ и фазу. Насыщение, компрессия и просадка питания лампового оконечника в IR не попадают, а реальный оконечник ещё и взаимодействует с импедансом динамика (подъём на резонансе корпуса и на верхах есть именно потому, что он нагружен конкретным кабинетом). Если IR оконечника снят на другой нагрузке, свёртка — это «эквалайзер оконечника перед кабинетом», а не полная модель связки.

**Проверка режима.** Кабинет с близким микрофоном к 8 кГц спадает на десятки дБ (так звучит динамик), а IR усилителя — нет, у него пологая «улыбка» на краях. По этому признаку (спад на 8 кГц глубже `CAB_HF_DROP_DB` = −12 dB относительно средней полосы) скрипт предупреждает, если режим, похоже, перепутан:

```
ВНИМАНИЕ — PWRAMPIR_6V6_Master70.wav не похож на кабинет (к 8 кГц нет спада динамика) — если это IR усилителя,
сложение с кабинетом не имеет смысла: сигнал идёт через усилитель и кабинет по очереди, нужен последовательный режим (--mode serial).

ВНИМАНИЕ — оба файла похожи на кабинеты (к 8 кГц спад глубже 12 dB) — последовательная свёртка двух кабинетов даёт
узкий «коробочный» звук. Для бленда кабинетов нужен параллельный режим.
```

**Имя результата** складывается из имён кабинетов: суффиксы прежней конвертации у входов (`_48k24b_984…`) отбрасываются, общий префикс пишется один раз (обрезается по последнему разделителю, чтобы не резать слово), различающиеся части соединяются через `+`. Баланс в имени — только если он не 50/50:

```
BD_DT_21GetDown.wav + OH_412_DZL_V30.wav, 70/30        → BD_DT_21GetDown+OH_412_DZL_V30_70-30_44k24b_1024.wav
BD_DT_21GetDown_48k24b_984.wav + BD_DT_01BongenBallen  → BD_DT_21GetDown+01BongenBallen_48k24b_984.wav
```

В последовательном режиме части имени соединяются через `_x_` (свёртка), баланса в имени нет: `PWRAMPIR_6L6_D50_P70_x_BD_DT_20HellHola_48k24b_984.wav`.

HPF и LPF в `irblend.py` нет: если нужны, результат можно пропустить через `iroptimizator.py`.
