# CLAUDE.md

Инструкции для Claude Code (claude.ai/code) при работе с этим репозиторием.

## Обзор

Открытые проекты и форки, каждый — в своей подпапке, со своим `README.md`. Лицензия — своя у каждого: IR-optimizator — MIT (`IR-optimizator/LICENSE`); tproxy-server — чужой код без лицензии (`tproxy-server/NOTICE.md`), MIT на него не распространяется. Корневого `LICENSE` нет намеренно — иначе GitHub показал бы весь репозиторий, включая чужой код, как MIT.

- **IR-optimizator/** — подготовка импульсных характеристик (IR) гитарных кабинетов для аппаратных загрузчиков с ограничением длины (Pangaea CP-16M и подобные) + анализ исходника; сводка по IR в PNG; объединение двух IR.
- **tproxy-server/** — веб-прокси для Telegram на Go; **не собственный проект**: копия форка `ststitov/tproxy-server` проекта `telegramdesktop/tproxy-server` (автор John Preston, лицензии нет), перенесена `git subtree add` с полной историей ради авторства. Собственный вклад — один коммит в тесте. Правки в `tproxy-server/` по возможности предлагать в оригинал; собственный код сюда не смешивать. Сборка: `cd tproxy-server && go test ./... && go build -trimpath -o tproxy-server ./cmd/tproxy-server`.

## Команды — IR-optimizator

```bash
cd IR-optimizator && source venv/bin/activate

# Интерактивно: спросит частоту (44/48), битность (16/24), длину (512/984/1024/2048), HPF, LPF
python iroptimizator.py "OH 412 DZL V30 JS.wav"

# Полностью из командной строки (вопросы не задаются)
python iroptimizator.py *.wav -o out --sr 48 --bits 24 --len 984 --hpf 60 --lpf 8000

# Повторный HPF после обрезки — давит низы, возвращённые коротким окном (→ *_hpfpost.wav)
python iroptimizator.py ir.wav --hpf 80 --hpf-after

# Нормализация по громкости вместо пика — IR разного характера одинаково громкие (→ *_loud.wav)
python iroptimizator.py *.wav --norm loudness

# Исправить полярность, удалить предзадержку; 16 бит — с TPDF-дизером (по умолчанию)
python iroptimizator.py *.wav --fix-polarity --trim --bits 16

# Минимально-фазовая версия (→ *_minph.wav); без флага скрипт сам порекомендует, если поможет
python iroptimizator.py ir.wav --minphase

# Сводка по IR в PNG; без аргументов — все *.wav в текущей папке, пары «исходник → результат» находятся сами
python irsummary.py
python irsummary.py *.wav -o compare.png

# Сводка по одному IR: АЧХ + распад + импульс + спад энергии + метрики
python irsummary.py "OH 412 DZL V30 JS.wav" -o summary.png

# Сравнение нескольких IR на одних осях (до 8 кривых)
python irsummary.py original.wav processed.wav -o compare.png

# Отдельный PNG на каждый файл
python irsummary.py cabs/*.wav --separate -o png/

# Объединение двух IR: первым вопросом — режим
python irblend.py A.wav B.wav                       # интерактивно
# параллельно — бленд двух кабинетов/микрофонов (выравнивание, проверка фазы, баланс)
python irblend.py A.wav B.wav --sr 44 --len 1024 --mix 70/30
# последовательно — свёртка «усилитель → кабинет»
python irblend.py PWRAMPIR_6L6_D50_P70.wav BD_DT_20HellHola.wav --mode serial

# Установка зависимостей
pip install -r requirements.txt
```

## Архитектура — IR-optimizator


Три утилиты: `iroptimizator.py` (подготовка IR, описана ниже), `irsummary.py` (сводка в PNG) и `irblend.py` (объединение двух IR — параллельно или последовательно) — обе описаны в конце раздела. В `iroptimizator.py` исходные WAV передаются позиционными аргументами, параметры обработки запрашиваются интерактивно (Enter = значение по умолчанию) либо задаются флагами; при неинтерактивном вводе (`< /dev/null`, cron) берутся значения по умолчанию и печатается, какие именно.

Параметры и умолчания: `--sr` 48000 (44/48/44100/48000), `--bits` 24 (16/24), `--len` 984 сэмпла (меню 512/984/1024/2048, флагом — любое целое > 0), `--hpf` и `--lpf` выключены (`0` отключает фильтр; по умолчанию оба 0 — в 984 сэмплах HPF не даёт чистого среза, см. «HPF и короткое окно» ниже; прежние умолчания 60 и 8000 Гц), `--norm` peak (peak/loudness, в интерактиве — отдельный вопрос), `--loudness-target` 8 dB (без `--norm` сам включает loudness, с `--norm peak` — ошибка). Частоты среза валидируются по `0 < f < fs/2` до обработки — иначе `butter` падает с невнятной ошибкой.

Порядок обработки в `process()`: стерео → моно, `--trim` (срез предзадержки в отсчётах исходника), ресемплинг (`soxr`, запасной путь — `resample_poly`), HPF 2-го порядка + LPF 4-го (`sosfilt`, каузально, на полной длине IR — чтобы хвосты фильтров не обрезались раньше времени; результат — эталон `reference`), `--minphase`, проверка знака пика и `--fix-polarity`, обрезка/дополнение до целевой длины, fade-out половиной косинусного окна длительностью `FADE_MS` = 2 мс (пересчитывается от целевой частоты: 96 сэмпл. @48 кГц, 88 @44.1), при `--hpf-after` — повторный HPF и повторный fade, нормализация — по пику до `PEAK_DBFS` = −1 dBFS или по громкости с ограничением пика тем же `PEAK_DBFS` — с защитой от деления на ноль.

`detect_predelay()` считает число сэмплов до первого превышения `PREDELAY_THR_DB` = −60 dB от пика и при ненулевом значении печатает предупреждение с остатком полезной части в сэмплах целевой частоты. Сигнал при этом не сдвигается и не обрезается — детект только предупреждает, что обрезка идёт от начала файла.

`detect_channel_conflict()` считает минимальную попарную корреляцию каналов и падение RMS при своде: корреляция ≤ `ANTIPHASE_CORR` = −0.5 — противофаза (без предупреждения на выходе была бы тишина), ниже `LOW_CORR` = 0.5 — гребёнка от разнесённых микрофонов, иначе просто сообщается факт сведения. Выход всегда моно.

Проверка исходника и верность конвертации: `detect_clipping()` ищет плоские вершины (`CLIP_RUN` = 3+ отсчётов подряд на пике канала) — надёжнее проверки на 0 dBFS, т.к. срезанный при записи файл могли потом нормализовать ниже нуля; отрицательный главный пик отмечается как инвертированная полярность (без предупреждения). `noise_floor()` возвращает словарь (`floor_db`, `reached`, `noise_ms`, `cut_db`): пол достигнут, если последние 10 % файла (но не меньше `NOISE_TAIL_MIN_MS` = 10 мс — на 2–3 мс затухающий хвост падает меньше 3 dB и ложно сходит за шум) не тише предыдущего такого же куска больше чем на `NOISE_PLATEAU_DB`; `noise_ms` — когда RMS-огибающая 5 мс опускается до пола + `NOISE_MARGIN_DB`; `cut_db` — уровень в точке обрезки; хвост цифровой тишины (ниже `DIGITAL_SILENCE_DB` = −120 dB) отрезается до оценки, иначе дополненный нулями IR получал «пол не достигнут, −600 dB» (найдено ревью), длина тишины (`silence_ms`) и конец импульса (`end`) выводятся отдельной строкой. Постоянное смещение проверяется только при достигнутом поле (в затухающем хвосте ненулевое среднее — сам сигнал): выше `DC_WARN_DB` = −60 dB и больше 4σ/√n. `conversion_fidelity()` сравнивает 1/3-октавную АЧХ результата с `stats['reference']` — отфильтрованным импульсом на полной длине, чтобы в отклонение попадали только обрезка, fade и повторный HPF; уровень выравнивается по медиане; полоса 100 Гц – 5 кГц с нижним краем не ниже 2·(частота/длина) и 1.5·HPF, верхним — ниже LPF/1.5 и полезной полосы; предупреждение выше `FIDELITY_WARN_DB` = 3 dB. Низы ниже рабочей полосы — отдельная строка `low_band_deviation()` (от `LOW_BAND_LO_HZ` = 40 Гц, при HPF не ниже 1.5·HPF, до нижнего края рабочей полосы): подъём (полка от незавершённого спада самого кабинета — корпус работает как HPF) и провал (резонанс корпуса ~50–60 Гц не успевает прозвучать) со знаком; уровень выравнивается по рабочей полосе, а не по медиане низов (иначе равномерный провал исчез бы). Выше `LOW_BAND_REC_DB` = 2 dB — рекомендация с прогнозом для следующей длины из меню на том же эталоне (совпадает с реальным прогоном). Строку добавили после того, как `irsummary` показал разницу на низах, которую основная оценка (от 2·разрешения окна) не видела: у `BD_HV_4_FinalEncore` на 1024 сэмплах провал −4.3 dB на 54 Гц при «отклонении 0.1 dB». Общая часть — `_deviation_curve()`. `octave_smooth()` живёт в `iroptimizator` и импортируется в `irsummary`.

Спектральный анализ — `_spectrum(x, sr, window)` в двух режимах, потому что одно окно не годится для обеих задач: `window=False` (только спад на хвосте, атака не тронута) даёт честную полезную полосу `detect_band()` по порогу `BAND_THR_DB` = −40 dB; `window=True` (выравнивание по началу импульса + окно Ханна) занижает полосу, но даёт динамический диапазон для `detect_content_cutoff()` — поиска провала `NATIVE_GAP_DB` = 30 dB над Найквистом кандидата из `SR_CANDIDATES`. Выравнивание делает оба измерения независимыми от предзадержки.

Детект отвечает только на вопрос «виден ли обрыв»: у гитарного IR содержание кончается на 10–19 кГц, полосы по обе стороны от 22.05 кГц одинаково пусты, и 44.1 от 48 кГц для такого материала неразличимы (проверено на синтетическом апсемпле: провал 14 dB против 44 dB у апсемпла с 22.05 кГц). Поэтому вывод — «обрывов спектра нет», а не «нативная частота такая-то».

Три условия, без которых детект врал: кандидаты выше `EDGE_OF_BAND` = 0.85 от Найквиста файла пропускаются (там стоит антиалиасный фильтр АЦП любой честной записи — иначе каждый файл 96 кГц объявлялся «апсемплированным с 88.2 кГц»); верхняя полоса сравнения ограничена 1.5·Найквиста кандидата, а не краем файла (иначе у широкополосного материала побеждал слишком низкий кандидат); предупреждение выводится только при обрыве ниже `target_sr / 2 * CUTOFF_MARGIN` (0.9) — при понижении частоты обрыв выше целевого Найквиста ничего не значит. Отдельно сообщается, если LPF выше полезной полосы и потому ничего не срезает.

`analyze_and_process()` обрабатывает один файл и возвращает строки отчёта списком, а не печатает по ходу: `main()` выводит их одним блоком под заголовком `[i/N] имя (sr, кадров)` и по флагам предупреждений и рекомендаций собирает финальную сводку. Для одиночного файла номер и сводка опускаются.

`process()` считает доли энергии в окне и снятую fade от энергии отфильтрованного импульса на полной длине, порог предупреждения `ENERGY_WARN_PCT` = 99 %; для файла без сигнала возвращается `None` вместо нулей, чтобы не выдавать «обрезан хвост» там, где сигнала нет. Fade-out применяется до нормализации, поэтому она учитывает его влияние на пик.

Ресемплинг — `soxr` (SoX Resampler, качество `VHQ`) с запасным путём на `resample_poly`, если модуль не установлен (тогда выводится предупреждение); использованный ресемплер печатается в отчёте. Измерено при 48 → 44.1 кГц: `soxr` давит алиасы на −190 dB, `resample_poly` — лишь на 8–16 dB (его FIR фиксированной длины размазывает переход на 20–24 кГц), при этом `soxr` ещё и быстрее. ffmpeg не нужен: форматы покрывает libsndfile, а `soxr` — та же библиотека, что внутри ffmpeg, но импортом, без внешнего процесса. Нормализация стоит последней намеренно: ресемплинг поднимает пик, восстанавливая интерсэмпл-пики (на тесте 0.9886 → 0.9990 при 48 → 44.1 кГц), поэтому нормализация до ресемплинга дала бы клиппинг при записи в PCM.

HPF и короткое окно: HPF применяется на полной длине, но обрезка до 984 сэмплов (20.5 мс, разрешение ~49 Гц) возвращает низы — на АЧХ ниже ~40 Гц полка около −30 dB. Это растекание полезного содержания из-за конечного окна, а не недоработка фильтра: оптимальная задача наименьших квадратов (минимум энергии ниже среза при сохранении верха) убирает лишь 0.01 п.п.; HPF 4-го порядка и удаление DC после обрезки не помогают. Механизм: HPF превращает низы в медленное колебание около среза, которое гасится лишь к ~40 мс (накопленная сумма отсчётов сходится к нулю только там); обрезка на 20.5 мс замораживает незавершённый остаток (+0.43 от пика против +0.24 у нефильтрованного IR) как постоянную составляющую — поэтому HPF+обрезка дают на 20 Гц больше (−28.5 dB), чем исходник без HPF (−35.7), хотя по отдельности HPF давит (−57.8), а обрезка низы не трогает. Отчёт показывает `energy_below()` — долю энергии готового импульса ниже HPF. Флаг `--hpf-after` повторяет HPF после обрезки (и заново накладывает fade — хвост фильтра за окном отрезается): при срезе 80 Гц 0.27 % → 0.10 %. Цена — смещение среза: два прохода Баттерворта 2-го порядка дают −3 дБ на 1.2465·fc (80 → ~100 Гц), `hpf_after_corner()` считает это из `HPF_ORDER`, фактический срез печатается в параметрах и отчёте. Убрать полку и сохранить срез одновременно в 984 сэмплах нельзя: поправка «оба прохода на fc/1.2465» возвращает −3 дБ на место, но второй проход на ~64 Гц упирается в предел разрешения окна, и полка возвращается (20 Гц −28.5 dB, энергия ниже 80 Гц 0.22 %). У среза рядом с пределом разрешения выигрыша нет, а самые низкие частоты становятся громче, поэтому при падении энергии меньше чем на 30 % (`HPF_AFTER_MIN_GAIN` = 0.7) выводится предупреждение; критерий «не выросло» тут недостаточен — при 60 Гц энергия падает в 0.89 раза, а 20–40 Гц становятся на 3–6 dB громче. `process()` возвращает `(сигнал, stats)`, где `stats` — словарь (`kept`, `lost_to_fade`, `below_hpf`, `below_hpf_pre`) или `None` для тишины.

Совпадающие имена исходников из разных каталогов (`a/cab.wav`, `b/cab.wav`) дают одно имя результата — запуск останавливается с ошибкой до вопросов (раньше второй файл молча затирал первый, найдено ревью).

`--hpf-after` требует включённого HPF: без `--hpf` в неинтерактивном запуске и с `--hpf 0` — ошибка с кодом 1 (раньше флаг тихо игнорировался с кодом 0, и ожидающий `_hpfpost` скрипт получал обычные файлы); в интерактиве вопрос про HPF становится обязательным (`ask_cutoff(required=True)`).

Нормализация по громкости: `ir_loudness()` — энергия IR после K-фильтра ITU-R BS.1770 (`k_weighting_sos()` пересчитывает коэффициенты для частоты дискретизации; на 48 кГц совпадают с таблицей стандарта до 1e-15), IR дополняется нулями на 200 мс, чтобы не потерять хвост фильтра. Цель абсолютная (`DEFAULT_LOUDNESS_TARGET` = 8 dB — чуть ниже кабинетов с близким микрофоном при пике −1 dBFS, 8.3–9.1 dB), а не «по самому тихому в пачке», чтобы совпадали IR из разных запусков; цель привязана к частоте дискретизации (на 48 кГц энергия того же импульса на 0.4 dB выше, чем на 44.1). Если пик при целевой громкости превысил бы `PEAK_DBFS`, усиление ограничивается, в `stats['short_db']` — недостача, в отчёте предупреждение. `stats` получает `loudness` и `peak_dbfs`; громкость печатается в обоих режимах. Мотивация — разброс: у пяти кабинетов с близким микрофоном он 0.8 dB, а IR с размазанной энергией при пиковой нормализации громче на 13.7 dB. Режим по пику побитово прежний.

Полярность, предзадержка, дизер: `--fix-polarity` переворачивает импульс при отрицательном главном пике — решение принимается в `process()` по уже обработанному сигналу (после фильтров и minphase), а не по исходнику, `stats['polarity']` = ok/inverted/fixed; `--trim` срезает `detect_predelay()` отсчётов исходника до ресемплинга (`process(trim=N)`), анализ шумового пола при этом сравнивает хвост со сдвинутой точкой обрезки; оба проверены на побитовое совпадение (исправленный перевёрнутый = исходный; срезанный с 500 сэмплами тишины = файл без неё; тестовый перевёрнутый файл нужно делать целочисленным отрицанием — запись −x через float в libsndfile несимметрична на 1 LSB). При 16 битах `quantize_pcm16()` квантует сама: libsndfile при записи float в int16 отбрасывает дробь (средняя ошибка −0.5 LSB, RMS 0.58 вместо 0.29); по умолчанию TPDF-дизер ±1 LSB с фиксированным `DITHER_SEED` (ошибка — ровный шум RMS 0.5 LSB, без дизера на тихом синусе выбросы искажений 46–72 dB над шумом), `--no-dither` — только округление. 24 бита по-прежнему пишет libsndfile (её смещение там −144 dBFS, файлы побитово прежние). Для кабинетов на 984–1024 сэмпла дизер на слух ничтожен (хвост −49 dBFS), это гигиена. Суффиксов эти три опции не добавляют — это исправления, а не варианты.

Минимальная фаза: `minimum_phase()` — гомоморфный метод (кепстр, БПФ с 8-кратным запасом против наложения, пол −120 dB под log); `scipy.signal.minimum_phase` не подходит — он для линейно-фазовых FIR и возвращает корень из АЧХ. Знак результата не зависит от исходника (строится по |X|), поэтому проверка полярности перенесена на обработанный сигнал. `--minphase` по умолчанию выключен; `minphase_benefit()` для каждого файла сравнивает обрезку исходной и минимально-фазовой версий на эталоне (отфильтрованный импульс полной длины) — рекомендация («РЕКОМЕНДАЦИЯ —», отдельный список в пакетной сводке) при росте энергии в окне ≥ `MINPHASE_GAIN_PP` = 1 п.п. или уменьшении отклонения АЧХ ≥ `MINPHASE_GAIN_DB` = 1 dB; с флагом — строка с эффектом «было → стало». Кабинеты с близким микрофоном почти минимально-фазовые (выигрыш ~0.01 п.п., рекомендации нет); «комнатный» синтетический IR — 64.6 → 67.4 % и 5.1 → 4.1 dB на 1024 сэмплах. Предзадержка при `--minphase` уходит сама. Без флага вывод побитово прежний.

Имя результата: `<исходное имя>_48k24b_984.wav` (частота, битность, длина), с `--hpf-after` — суффикс `_hpfpost`, с `--norm loudness` — `_loud`, с `--minphase` — `_minph`. `*.wav`, `*.png` и `venv/` — в `.gitignore` подсистемы.

`irsummary.py` — сводка в PNG (matplotlib, Agg): АЧХ со сглаживанием 1/N октавы по логарифмической сетке, спектральный распад CSD (для одного файла) либо разница АЧХ относительно первого файла (при сравнении), форма импульса, спад энергии, энергия по полуоктавным полосам (18 полос 31 Гц – 11 кГц: снизу с 31 Гц ради основного тона восьмиструнки — F#1 ≈ 46, Drop E ≈ 41 Гц; центры `BAND_CENTERS` = 1000·2^(n/2), полоса ±`BAND_HALF_WIDTH` = 2^(1/4), подписи — номиналы `BAND_LABELS`; полосы с центром ниже 2·частота/длина самого короткого файла закрашены, как зона на АЧХ; ширина фигуры 18 дюймов под 18 полос × до 8 файлов) и таблица метрик (длина, частота, пик dBFS, предзадержка, полосы −3/−10 дБ, пик АЧХ, спектральный центроид, время спада −20 дБ). Метрики отчёта импортируются из `iroptimizator` (`_spectrum`, `detect_band`, `detect_predelay`), чтобы цифры в утилитах совпадали.

Без аргументов (`files` с `nargs='*'`) берутся все `*.wav` текущей папки (`sorted(glob)`), это печатается; пустая папка — ошибка; больше 8 файлов без `--separate` — та же ошибка с подсказкой, молча на отдельные картинки не переключается. Пары и выравнивание: `find_pairs()` находит пары «X» → «X_48k24b_984…» по суффиксу iroptimizator (регулярка `RESULT_SUFFIX`, переименованный результат тоже; при нескольких кандидатах — самый длинный исходник), и разница АЧХ строится для каждого результата относительно его исходника, иначе — относительно первого файла. `align_curve()` по умолчанию выравнивает кривые по среднему уровню `ALIGN_BAND_HZ` = 200 Гц – 2 кГц (`--align peak` — прежнее выравнивание по максимуму: один резонанс сдвигал всю кривую). Серая зона на АЧХ — ниже 2·частота/длина самого короткого файла (там форму задаёт длина окна; та же зона, что строка «низы» в iroptimizator), пунктир на панелях времени — конец файла. В таблице — громкость `ir_loudness()`; длинные имена сокращаются с середины (`short_label()`), чтобы различающийся конец оставался виден.

Исправлено по ревью: «Спад −20 дБ» — от пика огибающей (с начала файла в предзадержке сразу находился «спад»); прямые подписи — внутри оси с раздвижкой (у правой границы с `ha='left'` и обрезкой их не было видно никогда); разница АЧХ при разной частоте — `np.interp(..., left=nan, right=nan)` вместо выдуманного продолжения; `--separate` с совпадающими именами из разных каталогов — ошибка до отрисовки.

Оформление — светлая тема, категориальная палитра из восьми цветов, различимых и при нарушениях цветового зрения, в фиксированном порядке, без циклирования; легенда при ≥ 2 кривых, заголовок с именем файла при одной; больше 8 кривых на одних осях отклоняется с советом взять `--separate`.

Вещи, найденные при отрисовке и закреплённые в коде: длина FFT не меньше 2¹⁷ (иначе 1/3-октавное сглаживание идёт ступеньками ниже 100 Гц — в полосу попадает меньше бина); огибающая спада считается скользящим RMS, а не Гильбертом (нелокальность даёт ложный всплеск на резком конце файла); окна панелей времени подбираются по спаду энергии (−30 дБ для импульса, −40 дБ для спада, не больше 50 мс), иначе 200-миллисекундный IR рисуется сплющенным в левый край; имя файла — первая колонка таблицы, а не подпись строки (подписи строк matplotlib рисует вне осей и они уезжают за край); `tight_layout` не используется — он несовместим с таблицей и цветовой шкалой, поля заданы явно, края снимает `bbox_inches='tight'`.

`irblend.py` — объединение двух IR, ровно двух (иначе ошибка). Режим — первым вопросом или `--mode`: `parallel` (по умолчанию; сложение — бленд кабинетов/микрофонов) или `serial` (свёртка `fftconvolve` — «усилитель → кабинет»: предзадержки обоих срезаются, т.к. при свёртке складываются; баланса нет, `--mix` с `--mode serial` — ошибка, `--mix` без `--mode` выбирает parallel без вопроса; отчёт — окраска АЧХ каждого входа и итоговая `tone_summary()`; проверено: АЧХ свёртки = сумма АЧХ входов в дБ с точностью 0.2 dB). Страховка от перепутанного режима — `looks_like_cab()`: спад на `CAB_HF_HZ` = 8 кГц глубже `CAB_HF_DROP_DB` = −12 dB относительно 200 Гц – 2 кГц — признак динамика в кабинете (у IR усилителя там пологая «улыбка», +3 dB); serial с двумя кабинетами и parallel с одним некабинетом — предупреждение. Имя при serial — через `_x_`, без баланса. Параллельный режим побитово прежний. Импортирует из `iroptimizator` чтение/свод/ресемплинг, `detect_predelay`, `ir_loudness`, `process()` (финальная обрезка, fade, нормализация), `quantize_pcm16`, вопросы и разбор аргументов. Интерактивно (или флагами): частота, битность, длина, баланс `--mix` (`mix_from_text()`: пропорция A/B «40/60»/«40:60», в том числе с суммой не 100 — «2/1» → 66.7, или доля A «40»; округление до десятой; по умолчанию 50/50), нормализация. `align_pair()`: срез предзадержки у обоих, затем подстройка сдвига B по взаимной корреляции первых `ALIGN_WINDOW_MS` = 5 мс в пределах ±`ALIGN_RANGE_MS` = 2 мс (порог −60 dB может сработать на тихом предвестнике); отрицательная корреляция — B переворачивается. Громкости выравниваются по K-взвешенной энергии до баланса (50/50 — поровну на слух); баланс — доли амплитуды. `notch_check()` — самый глубокий провал мощности смеси относительно суммы мощностей слагаемых (1/6 октавы, 100 Гц – 10 кГц), глубже `NOTCH_WARN_DB` = −6 dB — предупреждение. Подстройка по корреляции лечит всё, что лечится одним сдвигом, включая частичные фазовые расхождения (сдвиг уводит нуль гребёнки за полосу — синтетика «верх в противофазе» после сдвига на 3 сэмпла провалов не даёт); предупреждение остаётся для частотно-зависимого расхождения (all-pass на 1 кГц — −14.4 dB на 992 Гц). Проверено: A + (A, задержанный на 37 сэмпл., перевёрнутый, −6 dB) = обработка одного A до 1 LSB 24 бит; предвестник за 10 сэмпл. — подстройка +10. Имя: `blend_name()` — суффиксы конвертации входов отбрасываются, общий префикс один раз (обрезан по разделителю), части через `+`, баланс `_70-30` только если не 50/50, затем `_48k24b_984`, при `--norm loudness` — `_loud`.
